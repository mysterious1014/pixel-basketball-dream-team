# 像素篮球梦之队 · PIXEL DREAM TEAM

16-bit 像素风篮球卡牌收集微信小程序 —— **里程碑 1（MVP）+ 里程碑 2（羁绊 / 战术克制 / 异步 PVP 竞技场）+ 里程碑 3（时空进化 + 交易市场 + 王朝赛季 & 通行证）+ 里程碑 4（每日任务 + 钻石商店）+ 里程碑 5（竞技场加赛）本机完成版本**。
原生 WXML / WXSS / JS / JSON，**零第三方运行时依赖**，无需 `npm install`、无需构建。

> **合规定位（第三章，最高优先级）**
> 本项目为「个人学习 / 技术演示，非商业分发」。全部球员数值为**梦之队原创球探报告**，不来自 NBA 官方、2K 或任何商业数据源；程序内不含任何真实联赛 / 球队商标与 Logo 图像，球队仅以城市缩写文字出现。
> 若需对外展示，把 `config.js` 的 `compliance.fictionalMode` 改成 `true`，一键切换为风格化化名（库里 → 三分雨），设置页也提供同样的开关。

## 一、跑起来（微信开发者工具）

1. 打开**微信开发者工具** → `项目` → `导入项目`。
2. 目录选本仓库根目录（`E:\codex\像素篮球梦之队`）。
3. AppID 选 **测试号**（仓库里的 `project.config.json` 已写 `appid: "touristappid"`，未登录也能编译；若工具提示需要 AppID，点「使用测试号」即可）。
4. 点 `导入` → 自动编译。首个页面是 `pages/launch/launch`（启动页：像素 Logo + 版本 + 合规声明 + 收集进度），1.4 秒后自动 `switchTab` 到主页，也可点击屏幕立即进入。
5. 真机预览：基础库 `2.33.0`，`setting.urlCheck = true`（本项目**不请求任何网络地址**，域名白名单无需配置）。

调试快捷入口已写在 `project.config.json` 的 `condition` 里（编译模式下拉可选：启动页 / 招募 / 阵容 / 比赛）。

## 二、核心循环走查（约 5 分钟）

新手存档已给足资源（3 万金币 / 3000 钻石 / 30 张普通券 / 12 张高级券 / 120 体力），首屏即可体验完整闭环：

1. **招募**（Tab「招募」）→ 高级球探十连，看像素 `steps()` 逐帧翻牌；十连必出 SR+，UR 走 PRD 递增。
2. **编阵容**（Tab「阵容」）→ 「一键最强」自动排 5 首发 + 7 替补；总薪资必须 ≤ **12000 万工资帽**，超帽会红字告警且无法出战。也可「点选 A → 点选 B」交换（MVP 刻意不用拖拽，防真机卡顿）。
3. **PVE**（Tab「比赛」）→ 选关卡出战：扣体力 → Canvas 像素球场 + 逐回合文字直播回放 → 结算比分 / 星级 / 奖励。结算面板的 `seed` 可复制，用 `node tools/replay-battle.mjs --seed <seed>` 复现同一局。
4. **养成**（图鉴 → 点球员 → 详情页）→ 升级（金币）/ 升星（吃同名卡）/ 突破（金币 + 碎片）/ 装备三槽，六维雷达图（Canvas 2D）实时反映有效属性。
5. **一致性**：主页、招募页、阵容页三处的金币 / 钻石 / 体力 / 薪资数字全部来自同一个 Store，任意一页变更后其余页面自动同步（第十二章验收项）。
6. **战术克制**（Tab「阵容」→「战术」面板）→ 选进攻打法 + 防守策略，点右上「克制表」看 4 战术 × 3 防守的克制环；再去 Tab「比赛」打开任意关卡详情，看「战术侦察」：对手用什么防守、我方有多少出手吃克制、该换成哪套防守（可一键采纳）。比赛战报里带「克制 / 被克」角标的回合就是触发点。
7. **竞技场（异步 PVP）**（Tab「比赛」页首入口卡，或主页入口卡）→ 12 位原创对手的天梯，顺序解锁，每日 5 场、每场 10 体力（打满后可用钻石加赛 +5 场/日，40 钻/场，见下文「竞技场加赛」）；结算给 ELO-lite 积分变化 / 段位 / 连胜 / 竞技币（不发星级、不计赛季进度）；「历史对局」里任意一场都能用存档快照逐回合复现，不消耗次数与体力。

## 四、本地校验（不需要微信开发者工具）

`utils/` 与 `store/` 全是纯 CommonJS，`utils/storage.js` 在无 `wx` 的环境自动降级为内存存储，所以整套业务逻辑可以在 Node 里直接跑。要求 **Node ≥ 18**（本机 v22.2.0）。

| 命令 | 作用 | 退出码 |
|---|---|---|
| `node tools/verify.mjs` | **205 项回归**：配置口径 / 数据完整性 / 抽卡 / 比赛状态机 / Store 核心循环 / 工程完整性 / 页面组件工程 / 羁绊 / 战术克制 / 竞技场 / 页面层口径 / 时刻卡 / 竞技商城与解说 / 时空进化 / 交易市场 / 王朝赛季 & 通行证 / 每日任务 & 钻石商店 / 竞技场加赛 | 失败用例数（0 = 全绿） |
| `node tools/replay-battle.mjs --all --all-arena` | 18 关 + 12 位天梯对手逐个「同 seed 跑两遍逐字节比对」，验证比赛可复现（210 项） | 0 / 1 |
| `node tools/replay-battle.mjs --arena a03 --log 12` | 看某位天梯对手的逐回合战报（含双方防守策略与克制计数） | 0 / 1 |
| `node tools/replay-battle.mjs --stage s3-6 --log 12` | 看指定关卡的逐回合战报 | 0 / 1 |
| `node tools/replay-battle.mjs --seed <seed>` | 用比赛页复制出的 seed 复现同一局 | 0 / 1 |
| `node tools/gen-assets.mjs` | 重新生成全部像素 PNG（`--preview` / `--portraits-only` / `--icons-only`） | 0 |

`verify.mjs` 的 18 个分组：

- **A 配置与数值口径** —— OVR 权重和 = 100%、稀有度带覆盖 25–99 无缝无叠、薪资公式、文档示例（库里 = 92 / SSR / 1201 万）可复现。
- **B 数据完整性** —— 60 张卡每张 19 项属性齐全且在 25–99、六维雷达 19/19 覆盖、两个卡池各档位都有卡可发。
- **C 抽卡** —— 大样本概率收敛到公示表、十连必出 SR+、PRD 递增单调、90 抽硬保底兜底生效。
- **D 比赛** —— 可复现、回合数 = 配置、分节比分自洽、状态机相位转移合法、平局进加时。
- **E Store 核心循环闭环** —— 招募 → 得卡 → 编阵容（工资帽校验）→ PVE 出结果 → 养成提升数值；含体力不足拒绝出战、存档往返一致、体力 5 分钟/点上限 120。
- **F 工程完整性** —— `app.json` 每页四件套齐全、立绘 PNG 全部存在、**运行时代码零外链 URL**、所有 JS/JSON 可解析、装备槽位与加成键合法、18 关对手阵容可构建。
- **G 页面与组件工程校验** —— `usingComponents` 路径可解析、WXML 自定义标签都已声明、绑定的事件处理函数都存在、页面用 `Page()` / 组件用 `Component()` 注册、`components/` 下没有孤儿组件。
- **H 羁绊系统**（13 项）—— 羁绊数据完整性、同队分档（2/3/5）、同届的选秀年份窗口、宿敌与连线的触发条件、按 `playerId` 匹配（跨版本）、多羁绊叠加与单属性封顶、关闭开关回退里程碑 1 基线、**羁绊不改 OVR / 薪资**、阵容页显示与比赛实际生效一致、带羁绊仍可复现、加时段相位序列合法。
- **I 战术克制**（12 项）—— 克制表双向自洽、`auto` 按属性定调且一局只推一次、克制只乘 A/D、**关闭 == bonus0&mention0 的逐字节反向对照**、双方都盯人时必须 0 克制、行为对照（拉外线打收缩 > 打扩防，80 seeds 差值 > 2 分）、**侦察面板 == 引擎实际**、`bestDefenseAgainst` 建议 == 实测最优（9/9）、防守策略入库与老存档迁移。
- **J 竞技场**（13 项）—— 天梯数据完整性、`dayKey`/`dailyOf` 纯函数与跨天清零、ELO-lite 单调性与封顶、连胜加成、段位进度、结算口径（胜给钻石 / 首胜只叠一次）、**快照体积口径**（只存实例引用）、全链路落库、五类失败路径不动存档、**快照复现逐字节一致**、历史上限、存档往返、与 PVE 互不污染。
- **K 页面层口径**（14 项）—— 把 `Page`/`wx`/`getCurrentPages` 打桩后**真的在 Node 里挂载页面**：WXML 引用的字段必须都在同名 `.js` 里有来源（含反向对照）、页面目录都已在 `app.json` 注册、比赛页三模式（PVE / 挑战 / 回放）的结算字段与 commands 一致、战报克制角标 == `battle.counters`、竞技场页交互与跳转 URL 正确、主页/关卡页入口摘要 == `selectors.arenaSummary`、**全部 14 页 + 5 组件挂载不抛异常**、页面不得自产随机数。

文档第七章 7.3 的四类羁绊全部落地，判定逻辑集中在 `utils/bond.js`（纯函数），比赛与 UI 共用同一份 ⇒ 「阵容页看到的」和「比赛里生效的」不可能不一致。

|---|---|---|
| 同队 | 首发中同 `team` 的人数达 2 / 3 / 5 | `config.bond.teamTiers`（老队友 / 球队默契 / 王朝体系） |
| 同届 | 首发中同 `era` 且选秀年份跨度 ≤ 3 的人数达 2 / 3 | `config.bond.eraTiers`（同届之谊 / 黄金一代） |

三条设计裁决（详见 `config.js` 的 `bond` 段注释）：

1. **只加上场 5 人的战斗属性，不改 OVR / 稀有度 / 薪资** —— 否则工资帽会随站位组合漂移，第五章薪资公式与 7.2 校验就失去确定性。
2. **主客双方都吃羁绊** —— 公平，且让 BOSS 关的传奇阵容有自己的性格（如 s3-6 的湖人双星触发「老队友」）。
3. **`config.bond.enabled = false` 可一键回退里程碑 1 的战斗基线** —— 回归对照用。

羁绊按 `playerId` 匹配，所以同一名球员的**任意版本**（新秀 / 现役 / 巅峰传奇）都能触发连线；但同队羁绊看的是**卡牌所属球队**，因此换个版本可能激活或断开同队羁绊（例如詹姆斯现役版属 LAL、巅峰版属 CLE）—— 这正是第五章版本系统与羁绊的交叉点。

阵容页有「羁绊」面板与「羁绊图鉴」弹层（列出全部宿敌 / 连线及还差谁），球员详情页有「羁绊连线」区块，比赛结算面板列出双方本场生效的羁绊。

## 六点六、战术克制与竞技场（里程碑 2）

### 战术克制：4 套进攻战术 × 3 套防守策略

| 防守策略 | 掐住 | 被惩罚 |
|---|---|---|
| 人盯人 | —（不偏科） | —（不被白吃） |
| 收缩护筐 | 内线强攻 / 突破分球 | 中距离单打 / 外线三分 |
| 外线扩防 | 中距离单打 / 外线三分 | 内线强攻 / 突破分球 |

- **生效点只有一处**：`utils/battle.js#resolve()` 里，吃克制的一方 A（进攻属性）或 D（防守属性）× 1.1，然后再各自乘 `rand(0.85, 1.15)`。**不改 OVR / 稀有度 / 薪资 / 星级门槛**，所以工资帽与图鉴口径完全不受战术影响。
- **出手分布不变**（`config.battle.counter.tacticWeightMul = 1`）：实测把它调到 1.6 会让 3 打法 × 3 防守的净胜分差从 ±3 分拉到 ±14 分，直接击穿 PVE 的星级门槛（净胜 4 / 9 / 15）。「换打法」是主动决策，「吃克制」是被动结果，两者刻意分开。
- **`auto` 定调**：默认防守策略是 `auto`，按上场五人的 `block` / `steal` / `defIQ` 均值推导（盖帽高 → 收缩、抢断高 → 扩防、意识高 → 人盯人），一局只推一次并在 UI 上标注「（按属性自动定调）」。
- **侦察判据 = 净得分价值**：`selectors.counterShare()` 既算「吃克制 / 被克的出手占比」，也按战术分值（三分 3、其余 2）加权成得分价值；`bestDefenseAgainst()` 取对手占便宜最少的那套防守作为建议。I 组用 2 打法 × 3 防守 × 60 seeds 的实测对照验证建议与实测最优 **9/9 一致**，另有断言直接比对「面板显示 == `battle.simulate` 实际」。
- **落点**：阵容页「战术」面板（打法 + 防守 chips、本局定调、当前打法克制结论、克制表弹层）、关卡详情「战术侦察」、天梯每行的克制判定与一键采纳、比赛战报的「克制 / 被克」角标与结算面板的双方计数。
- 一键回退：`config.battle.counter.enabled = false` ⇒ 战斗回到里程碑 1 基线（I 组有「关闭 == 开启但 bonus=0 & mention=0 逐字节一致」的反向对照）。

### 异步 PVP 竞技场

| 项目 | 口径 |

| 次数与体力 | 每日 5 场（按本地日期重置，`dayKey` 由 commands 注入，`utils/` 不碰 `Date.now()`），每场 10 体力 |
| 加赛（里程碑 5） | 免费 5 场打满后可用钻石加购当日次数：40 钻/场、每日最多 +5 场（`config.arena.extraChallenges`），与 `usedToday` 跨天一起清零；只加场次、不卖战力，竞技币基线（5 场 = 100 币/日）不变 |
| 产出 | 金币 / 钻石（只给胜方）/ 碎片（负 0.3、平 0.5 折算）+ 经验 80/55/30 + 竞技币 20/5 + 首胜额外奖励（只叠一次） |
| 与 PVE 的隔离 | **不发星级、不写 `season.cleared`、不计入执教战绩**；反过来打关卡不动积分与每日次数（J / K 组双向断言） |
| 竞技币 | 每胜 20 / 每负 5，**在竞技商城消费**（时刻卡为商城独占，见下文「竞技商城」） |

## 六点七、名场面时刻卡 / 竞技商城 / 竞技场解说（里程碑 2 收尾）

### 名场面时刻卡：随身装备，只在比赛内触发

文档第八章点名的两张卡按原文数值落地，其余 12 张是同一体系的原创扩展（`data/moments.js`，共 14 张，N2 / R4 / SR4 / SSR2 / UR2）：

| 卡 | 稀有度 | 效果（`effects` 折叠后的乘数） | 生效点 |
|---|---|---|---|
| **35 秒奇迹** | SSR | 末节及加时**外线三分**：属性对抗 A ×1.2（文档原例） | `utils/battle.js#resolve()` |
| **81 分之夜** | UR | 出手人权重 ×2，不限战术 / 节次（文档原例） | `utils/battle.js#pickShooter()` |
| 三双之夜 | UR | 出手权重 ×1.6 + 全战术 A ×1.08 | 两处 |
| 禁区怪物 | SSR | 内线强攻 A ×1.15 + 内线出手权重 ×1.5 | 两处 |
| 关键球基因 | SR | 末节及加时全战术 A ×1.10 + 出手权重 ×1.15 | 两处 |
| 海报级暴扣 | SR | 内线强攻 A ×1.12 + 内线出手权重 ×1.35 | 两处 |
| 脚踝终结者 / 中距离教科书 | SR | 突破分球 / 中距离单打 A ×1.13 | `resolve()` |
| 打成二加一 / 一条龙快攻 / 底角狙击 | R | 单一战术 A ×1.08 – ×1.09 | `resolve()` |
| 下半场觉醒 | R | 第 3 节起全战术 A ×1.07 | `resolve()` |
| 热身完毕 / 主场声浪 | N | 中距离单打 A ×1.05 / 出手权重 ×1.2 | 单处 |

- **只有两种效果**：`attr`（属性对抗里 A 的基础值 ×`mul`，与战术克制的 `bonus` **同层**，文档 7.4 的公式形状与量纲都不变）与 `shooter`（`pickShooter` 的权重 ×`mul`）。两者都支持 `tactics` / `minQuarter` / `maxQuarter` 三个可选过滤条件，多条 `effects` 同类相乘。
- **全部是确定性乘数，不掷额外的骰子** ⇒ 没佩戴时随机流与里程碑 2 基线逐字节一致（L 组把 18 关 PVE + 12 位天梯逐个开/关对照，diff 必须为 0）。
- **加时的 `quarter` 是 5、6…**，所以 `minQuarter: 4` 天然覆盖加时 —— 关键球类卡就该在加时继续生效。反过来 `pickShooter` 的 `quarter` 是新加的第 4 参，老调用方不传时带节次条件的卡一律不命中，不会误触发。
- **不改 OVR / 稀有度 / 薪资 / 属性面板**（与羁绊同一条纪律）：工资帽与佩戴组合无关，详情页属性表不会因为换一张卡而跳动。玩家看到的是「实战触发」，不是「面板膨胀」。
- **堆叠刷不出数值**：出手权重是**相对量**，五人同戴一张「81 分之夜」与没人戴**逐字节相同**（L 组第 4 条锁死）。一张卡够改变打法，五张也不会变成数值碾压 —— 这是「时刻卡是打法改变而非直接战力」的机制层保证。
- **实测 == 文案**：200 seeds 下末节三分的 `A_eff` 均值提升 **19.95%**（卡面写 +20%）；一人佩戴「81 分之夜」后其出手占比从 **19.3% → 32.8%**（理论值 2/(2+4) = 33.3%）。注意只能做**聚合均值**对照，不能逐回合对照：A 提高后「`aEff >= dEff` 直接命中」会少消耗一次 `rng.chance`，随机流在首次判罚分歧处就错开了，那是引擎的正确行为。
- 与装备完全同构的穿戴语义：卡实例在 `state.bag` 里扣 1，戴到某名球员身上，换下时退回背包 ⇒ `config.moment.uniqueInstance`（一份卡只能一人戴）自动成立，不需要额外的占用表。
- 落点：球员详情页「时刻卡槽」+ 换卡弹层、阵容页时刻卡面板、背包「时刻卡」分页（含图鉴进度）、比赛结算面板列出双方本场生效的卡（按 `uiMaxListed` 折叠为「等 N 项」）。
- 一键回退：`config.moment.enabled = false`（乘数恒为 1、文案清空、槽位隐藏，但**已佩戴的卡仍能取下来** —— 关闭开关不该把玩家的卡锁死在身上）；`config.moment.globalScale` 是唯一的总强度旋钮，缩放形状为 `1 + (mul − 1) × globalScale`，所以「无效果」的不动点始终落在 1，缩放不会凭空造出加成。

### 竞技商城：给竞技币一个消费出口

此前竞技币只累积不消费，是经济上的死路。现在 `data/shop.js`（18 条）接上出口：

| 分组 | 内容 | 定价 | 限购 |
|---|---|---|---|
| 名场面时刻卡（14 条） | 全部时刻卡，**商城独占**（不打天梯永远拿不到） | N 150 / R 320 / SR 700 / SSR 1500 / UR 3200 | 3 / 3 / 2 / 1 / 1 |
| 养成补给（4 条） | 碎片 ×5、体力药水、高级招募券、金币袋 ×2 | 60 – 400 | 不限购 |

- **定价按「满收入日」倒推**：竞技币日收入上限 = 每日 5 场 × 每胜 20 = **100 币**（免费 5 场的基线 = 定价倒推口径；里程碑 5 加赛可再买场次、按场次多产币，但那是钻石支出侧的加速，不松动零氪曲线），所以 N ≈ 1.5 天、R ≈ 3 天、SR ≈ 7 天、SSR ≈ 15 天、UR ≈ 32 天 —— 与第九章「零氪 30 天可达全 SSR 阵容，UR 为长期追求」同一条曲线（M 组断言最贵的一件 ≤ 40 个满收入日）。
- **限购**记在 `arena.shopBought`。因为一份卡只能一名球员戴，`limit` 直接等于「最多几名球员能吃到这张卡」；SSR/UR 限 1 件是防崩坏的关键。
- **只收竞技币**，不收金币 / 钻石：竞技币是 PVP 专属产出，混用会让 PVE 玩家也能买到 PVP 奖励，破坏「打天梯才有回报」的动机；反过来 PVP 也不该能买断 PVE 养成主线。
- 三道闸（开关 → 限购 → 余额）在 `commands.buyArenaItem` 与 `selectors.shopView` **各判一次且口径必须一致**，M 组用「18 条目 × 3 档余额」交叉校验 `canBuy === ok`，防的是最难查的那类 bug：按钮亮着、点了没反应、日志里什么都没有。
- 入口：竞技场页的竞技币行 + 底部「竞技商城 · 兑换时刻卡」按钮 → `navigateTo('/pages/bag/bag?tab=shop')`（背包不是 tabBar 页，不能用 `switchTab`）。背包页的「钻石商店」已由里程碑 4 转正为补给直购（体力药水 / 金币袋 / 招募券），见下文「每日任务与钻石商店」。

### 竞技场专属解说：合并候选池，不掷额外的骰子

`data/commentary.js` 从 80 条扩到 **117 条**，其中 8 类事件共 **37 条**是竞技场专属（`arenaMake2` / `arenaMake3` / `arenaMiss` / `arenaBlock` / `arenaHotStreak` / `arenaQuarterStart` / `arenaWin` / `arenaLose`）。

- **做法是把专属模板合并进候选池，不是「先掷一次骰子决定用哪套文案」**：`pick()` 每次调用固定消耗 1 个随机数，合并候选池不改变消耗次数 ⇒ 比分与整条随机流完全不受影响，只有文字变（M 组用 30 seeds 验证「数值与回合事实逐字节相同、文案 30/30 不同」）。若改成掷骰混入，就会多消耗一个随机数，把之后每一回合的掷骰全部推移，PVE 与竞技场的基线一起报废。
- 混合比例 = 专属条数 / 合并后总条数，**想调浓淡就增减条数，不要加掷骰**。
- `battle.simulate({ mode: 'arena' })` → `result.mode` 回带；快照复现必须传同一个 `mode`（`utils/arena.js#snapshotOf` 已存），否则文案对不上 ⇒「逐字节一致」会红。
- 没有专属池的类型（`rebound` / `quarterEnd` / `ot` …）在 arena 模式下安全退回基础池。

| 倍速 | 单局时长 | 说明 |
|---|---|---|
| 1× | ≈ 146 秒（2.4 分钟） | 文档第二章「单局 2–3 分钟」 |
| 2× | ≈ 73 秒 | |
| 4× | ≈ 37 秒 | = 里程碑 2 之前的默认手感，急性子玩家的出口 |

## 六点八、时空进化（里程碑 3 首块）

「时空进化」把「同一球员的多个版本」变成养成材料 —— **分解**版本卡得巅峰碎片（按球员隔离），**新秀版 + 现役版成套献祭**拿 1.5 倍，碎片攒够后**合成巅峰传奇版**（不入卡池、不碰工资帽）。

| 路径 | 消耗 | 产出 |
|---|---|---|
| 分解版本卡 | 一张非巅峰版本卡（不在阵容、该球员未拥有巅峰版） | 巅峰碎片 = 出厂稀有度档位（N 2 / R 4 / SR 8 / SSR 16 / UR 32） |
| 成套献祭 | 该球员新秀版 ×1 + 现役版 ×1 | 碎片 = `floor((v1 + v2) × 1.5)`（詹姆斯 36 vs 分开 24、库里 30 vs 20） |
| 合成巅峰版 | 碎片 ≥ `peakCost`（SR 20 / SSR 30 / UR 40） | 一张巅峰传奇版实例（Lv.1 / 1★ / `source=evolution`） |

- 数据现状：**20 位球员拥有巅峰传奇版（20 张巅峰卡）**= 13 位纯巅峰退役传奇（奥尼尔 / 魔术师 / 伯德 / 邓肯 / 加内特 / 诺维茨基 / 韦德 / 姚明 / 麦迪 / 艾弗森 / 卡特 / 奥拉朱旺 / 皮蓬）+ 7 位多版本球星（詹姆斯 / 库里 / 杜兰特 / 哈登 / 威少 / 乔丹 / 科比）；13 位纯巅峰传奇没有非巅峰版本卡、碎片材料实际不可得（巅峰卡只能通过招募获得），实际能打出进化的就是这 7 位。文班亚马只有新秀 + 现役、没有巅峰版，面板显式说明「不参与时空进化」而不是装死。7 位里只有詹姆斯与库里同时拥有新秀 + 现役，能打出完整成套献祭。
- 六条裁决写在 `config.evolution` 注释（改前必读）：碎片按球员隔离；分解按**出厂**稀有度计值（先升满再拆不套利，收益可公示）；巅峰卡不可分解、已拥有巅峰版则三条路径全冻结；材料必须在阵容外（硬拒绝）；允许分解「最后一张该版本」（软提示，避免「差 4 碎片无路可走」）；成套献祭价值严格大于分开分解。
- 分层：纯函数 `utils/evolution.js`（零随机、零时间）→ 校验 `store/reducers.js` → 编排 `commands.salvageCard / evolvePair / synthPeak` → 视图 `selectors.evolutionView`；存档新增 `state.evolution.shards`（老档迁移自动补空壳）。
- 一键回退：`config.evolution.enabled = false`（三个命令全部拒绝，面板仍可打开并给可读文案）。零新页面、零新卡、零新依赖，不动战斗随机流与工资帽。

## 六点九、交易市场（里程碑 3 第二块）

`config.market.enabled = true` 时开放：**每日橱窗**（5 格：基础 / 轮换 / 焦点 / 名将 / 神秘，权重在 `data/market.js`）用金币**买入非巅峰版本卡**，**出售**手头多余的卡换金币，「刷新」花 300 金币重掷整架橱窗。

| 环节 | 口径 |
|---|---|
| 买入价 | N 900 / R 1800 / SR 3600 / SSR 7200（UR 14400 档随 `rarity.order` 预留，当前池无 UR） |
| 卖出价 | = 买入价 ÷ 3（买下立刻卖出净亏 2/3，从机制上杜绝刷市场套利） |
| 刷新 | 300 金币 / 次，`state.market.rerolls + 1` ⇒ 整架 5 格重掷 |
| 货架 | `utils/market.js#shelfOf(dayKey, rerolls)` 纯函数：同 (日期, 刷新次数) 跨设备逐字节同一份货架；每格固定消耗 2 个随机数，同天无重复卡；1000 天采样 SSR 日出现率 ≈37% |

- 六条裁决写在 `config.market` 注释（改前必读）：只流通非巅峰卡（巅峰卡走招募 / 时空进化，金币买断会打崩两条线）；价格按**出厂稀有度**计（养成不改变价格）；卖价 = 买价 ÷ 3；橱窗不限购；**货架与「已拥有些什么」无关**（否则买一张 → 货架漂移）；出售允许「最后一张」（软提示），硬拦只有「在阵容中 / 巅峰卡」。
- 分层：纯函数 `utils/market.js`（零随机、零时间）→ 校验 `store/reducers.js`（用 action 自带的 `(dayKey, rerolls)` 重算货架做第二道校验）→ 编排 `commands.marketBuy / marketSell / marketRefresh` → 视图 `selectors.marketView`；存档新增 `state.market.rerolls`（老档迁移自动补空壳）。
- 卖出的卡从收藏移除，**卡上的装备与时刻卡自动退回背包**（与分解 / 献祭同口径，通知里写明去向）。
- 入口：主页快捷入口 + 个人页「交易市场」摘要面板 → `/pages/market/market`（非 tabBar 页，一律 `navigateTo`）；市场页买入 / 出售 / 刷新都带二次确认（`wx.showModal`）+ toast，买入行显示「已有 ×N」、出售行给「最后一张 / 附件退回」软提示。
- 一键回退：`config.market.enabled = false`（三条命令全部拒绝、页面给可读文案）。零新依赖、不动战斗随机流与工资帽。

- 结算面板显示「赛季积分 +N（升至 X 级）」与任务达成行；**历史回放不重发、不显示**。入口：主页快捷入口 + 个人页「王朝赛季」摘要面板 → `/pages/dynasty/dynasty`（非 tabBar 页，一律 `navigateTo`）。

## 六点十一、每日任务 & 钻石商店（里程碑 4）

`config.daily.enabled = true` 时开放：任意结算（PVE / 天梯）与抽卡自动推进 5 条每日任务的计数器，**达成即自动发奖、无需手动领取**（一日内计数单调递增 ⇒ 每天至多发一次）；背包页「任务」分页 = 每日任务 + 经理目标，钻石商店从「诚实占位」转正为补给直购。

| 任务 | 目标 | 奖励 |
|---|---|---|

## 六点十二、竞技场加赛（里程碑 5）

用户反馈「竞技币不够，挑战 5 次上限了」的直接回应：免费 5 场打满后，可以用**钻石加购当日挑战次数** —— 40 钻/场、每日最多 +5 场（当日总上限 10 场），跨天与 `usedToday` 一起清零。

| 项 | 口径 |
|---|---|
| 单价 / 上限 | 恒定 40 钻/次、每日 +5（`config.arena.extraChallenges`）；刻意不做阶梯价，「加钟」不该让玩家反复心算 |
| 每场体力 | 10（与免费场次同，体力是第二道闸） |
| 免费基线（不动） | 5 场 / 100 竞技币/日 —— 竞技商城定价倒推只认这条基线，加赛属**钻石支出侧**的加速器 |
| 购买前置 | 无 —— 允许预先加购再一口气打完；误消费由二次确认弹窗兜 |
| 读侧封顶 | `utils/arena.js#dailyOf` 对 `extraToday` 先归一再封顶 ⇒ 手改存档 / 降级残留换不来无限挑战，既有调用方零改动 |
| seed 顺延 | 仍是 `arena-<对手id>-<dayKey>-<当日第几场>`，加赛落在 `-6`~`-10`，与免费场次无碰撞；加赛场次快照可与原局逐字节复现 |

- 五条设计裁决写在 `config.arena` 注释（改前必读）：与免费次数共用一条进度（存档只加 `arena.extraToday` 一个计数器，`dayKey` 仍由 commands 切片）；价格恒定；上限 +5；不设「先用完免费」前置；`enabled=false` 一键关闭（命令拒绝、页面入口消失、存档字段保留，回里程碑 2 口径）。
- 三层对账：reducer 按 `(dayKey, n, 单价)` 三个字段重算（与 `MARKET_BUY` 同规，直派伪造 payload 一律原样返回 state）→ `commands.arenaBuyExtra` → 视图 `arenaView.extra / arenaSummary.extra`；「次数用尽」的失败文案会自动提示加赛出口。
- 落点：竞技场页「加赛 N/5 · 40 钻/场」行（买满显示「今日已购满 +5」、钻石不足显示差额）+ 二次确认；比赛页再战拦截文案同步指向加赛。
- 一键回退：`config.arena.extraChallenges.enabled = false`（R 组第 9 条：命令拒绝、视图关闭、同 seed 战斗投影逐字节不变 —— 加赛与战斗引擎零耦合，它只动竞技场的「次数账」）。
- 同轮顺手收口两处陈旧占位：设置页音效文案改为「当前版本未接入音频输出，开关仅保存偏好」（提示词文档通读无音频要求，不发明功能）；`config.js` 的 `VERSION / MILESTONE` 回填 `0.5.0-m5 / M5`（M4 轮漏更，R 组第 12 条锁死「后缀与里程碑一致」防再犯）。
